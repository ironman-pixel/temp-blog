## 프로젝트: 사내 MLOps (Kubeflow, LakeFS, MinIO, MLflow)통합 플랫폼

![[KUBEFLOW_AUTH_FLOW.svg]]
**역할**
Kubeflow 파트 전담 (Jupyter Notebook, PVC, Pipeline 관리 API 연동 모듈 개발)

**Situation**
- Kubeflow Dashboard를 제어해야 하나 **공식 REST API 문서가 부재**한 상황
- 브라우저 세션 기반의 복잡한 인증 체계(Istio + Dex + OIDC Authservice)로 인해 단순 헤더 방식의 **Server-to-Server 통신 불가**

**Task**
- 브라우저의 개입 없이 **Spring Boot 백엔드가 자체적으로 OIDC 인증을 수행**하고 Kubeflow 리소스를 제어할 수 있는 자동화 파이프라인 구축

**Action**
- **트래픽 리버스 엔지니어링:** 브라우저 네트워크 패킷을 추적하여 비공식 API 엔드포인트(URL, Method, Payload) 및 인증 헤더 구조를 블랙박스 테스트 방식으로 역산출
- **Spring WebClient 기반 OIDC 핸드셰이크 구현:** 브라우저의 연속된 HTTP Redirect 체인을 백엔드에서 모사하여 자동 추적하도록 통신 모듈 개발
- **CSRF 및 세션 쿠키 인젝션:** OAuth2 Callback 과정에서 state 파라미터가 유실되는 문제를 파악. 이를 동적으로 추출해 `oidc_state_csrf` 쿠키로 수동 인젝션하여 최종 세션 및 XSRF Token 획득 성공
- **인증 만료 Failover:** 세션 만료 시 반환되는 특정 HTML 응답 패턴을 인터셉터로 감지, 자동으로 인증을 재시도하고 토큰을 갱신하는 에러 핸들링 로직 추가

**Result**
- 문서화되지 않은 Kubeflow의 통신 규격을 분석해 **사내 MLOps 플랫폼 백엔드에 통합**
- OIDC/OAuth2의 리다이렉션 흐름과 CSRF 검증 원리를 이해하고 **브라우저 종속적인 인증을 서버 간 통신 아키텍처로 전환**

## 프로젝트: 국방과학기술표준분류체계

**역할**
PDF 비식별화 저작 도구 개발

**Situation**
- pdf 파일을 비식별화 처리하는 기능이 담긴 무료 오픈소스가 없고 상용 솔루션 도입은 비용/라이선스 제약으로 불가능한 상황
- 전용 UI 와 백엔드 처리가 결합된 자체 개발 툴이 요구됨

**Task**
- 상업적 이용 제약이 없는 오픈소스 렌더링 엔진과 백엔드 문서 파싱 패키지를 결합하여 PDF 렌더링부터 목차 수정, 바운딩 박스 좌표 추출, 최종 비식별화 파일 생성까지 전 과정을 아우르는 시스템을 자체 구축

**Action**
- **비정형 데이터 모델링 및 파일 처리:** PDF 목차 데이터 구조와 페이지별 바운딩 박스 데이터를 매핑할 수 있도록 DB 스키마를 설계하고, 원본 PDF에서 메타데이터를 파싱 및 재생성하는 백엔드 파이프라인 개발
- **AI 기반 풀스택 쾌속 구현:** 주력 분야가 아닌 PDF 뷰어 개발은 Cursor IDE의 AI 챗 인터페이스 적극 활용. 낯선 라이브러리의 구조와 구현 방향을 AI와 페어 프로그래밍 방식으로 조율하며 단기간에 시각화 및 제어 UI 구현
- **데이터 흐름 최적화:** 백엔드에서 PDF 구조를 분석해 프론트로 전달하고 프론트에서 편집된 데이터만 백엔드로 전송해 시스템 부하와 네트워크 페이로드 최소화

**Result**
- 상용 솔루션 의존 없이 맞춤형 비식별화 저작 도구를 개발하여 라이선스 비용 절감
- AI 어시스턴트를 활용해 개인의 기술 스택 한계를 넘어 비즈니스 요구사항 충족

## 프로젝트: 도심융합구축사업

**역할**
CCTV Re-identification 이미지 저작도구 개발

**Situation:**    
- CDN 및 클라우드 스토리지 도입이 불가능한 인프라 환경
- 인가된 사용자만 안전하게 이미지에 접근해야 하는 요구사항 존재

**Task:**
- Base64 인코딩 방식은 네트워크 페이로드 증가 및 데이터베이스/WAS 부하를 유발하여 배제 필요
- 보안성(인가된 접근)과 서버 성능(빠른 응답 속도 및 리소스 절약)을 모두 만족하는 이미지 서빙 아키텍처 설계

**Action:**
- Django에서 사용자 권한을 검증하고 만료 시간이 있는 Signed URL을 자체 생성하도록 로직 구현
- 인증이 완료된 요청에 한해 `X-Accel-Redirect` 헤더를 응답하여 Django 워커의 블로킹 없이 Nginx가 직접 파일을 비동기적으로 서빙하도록 시스템 구성

 **Result:**
- Django WAS의 스레드/워커 점유 시간을 극적으로 단축하여 동시 접속 처리 능력 향상
- Base64 대비 네트워크 대역폭 절감 및 Nginx의 효율적인 정적 파일 I/O 활용으로 응답 속도 개선
- URL 만료 및 권한 검증을 통한 안전한 파일 보안 체계 구축

## 프로젝트: 이미지의 객체 기반 질의응답 데이터 구축

**역할**
LabelOn 라벨링 플랫폼 통합 솔루션 개발

**Situation**
- 온프레미스 3대의 WAS가 로드밸런싱되는 분산 환경에서 다수의 유저가 동시에 새로운 작업을 요청하는 상황
- 두 가지 동시성 이슈 발생 위험 존재:
    1. 여러 유저에게 동일한 작업 할당
	2. 한 유저에게 두개 이상의작업 할당

**Task**
- RDBMS Lock으로 인한 성능 저하와 커넥션 풀 고갈은 피하면서, 분산 환경에서도 데이터 정합성을 보장하는 작업 할당 시스템 구축

**Action**
- **Atomic 연산을 활용한 안전한 분산 큐 설계:** DB 조회 대신 Redis의 `SPOP` 명령어가 가진 싱글 스레드 기반의 원자적 특성을 활용해 대기열을 구성. 다중 WAS 환경에서 수많은 요청이 동시에 유입 되더라도 1개의 작업은 반드시 1명의 유저에게만 Pop 되도록 하여 **유저 간의 작업 경합 차단**
- **Redis SETNX 기반 유저별 분산 락 구현:** 사용자 ID 기반의 분산 락을 `SETNX`로 구현하여 **단일 유저의 다중 요청 방어**. DB 트랜잭션 커밋이 완료된 이후 락이 해제되도록 구현
- **Deadlock 방지:** WAS 서버가 비정상 종료되더라도 다른 작업에 영향을 주지 않도록 락에 `TTL(ex=5)` 설정

**Result**
- DB Lock 없이 Redis 단에서 경합을 처리하여 분산 서버 환경에서도 데이터 정합성 이슈 0% 달성 및 데이터베이스 리소스 방어
